## 三、9-21 全程中断的根因分析（100Hz 黑匣子实证）

现象：主循环 73.4s（走线中段）操作员急停——目测"关节抬不起臂、
原位反复抖动、用不上力"。

数据结论（FFT 带通 + 力矩分解）：
1. **主关节无力不足**：力矩峰值 J2 6.1 / J1 5.6 Nm = 预算 0.2~0.25×，
   **零饱和帧**；中断前跟踪 mean 1.21°/max 3.43° 仍正常；
2. **无高频抖动**：5~15Hz 段全关节 0.03~0.1°（不可见）；
3. **真实症状 = 0.5~2Hz 全臂低频摆动**：J2 峰峰 1.09°(平稳段)→2.93°
   (悬伸段)，J4 1.84→2.26°，J5 0.48→1.84°——平稳段→悬伸段增 2.7×；
4. **机制判定**：摆动周期与驱动积分器时间常数吻合（J2 ki=12，补 2Nm
   需 ~2.8s）→ **URDF 外未建模负载（线缆拖拽）在悬伸位形增大 → 重力
   前馈欠补偿 → 积分器补上又过冲 → 0.5~2Hz 猎振**。与位形相关
   （第二半程悬伸更久），非随机、非退化、无危险（远离一切限位/饱和）。

- **J6 疑点（0914 遗留）**：输出耦合疑似打滑 ~88° 未排除，最紧关节

  永远用 `rl_exec --return-home`；
- **Ctrl+C**：一次 = 位置保持（SIGINT 已修复，真正生效）；两次 = 强停
  （滑回 JTC，有限速保护但避免）；

- **反馈断流 = 锁存**：`/joint_states` 断 >1.5s → 锁存 TRIPPED 不回位
  （无反馈不主动运动），人工排查后 reset；
- **两源同活跃 = 冻结**：RL 与 MPC 注入话题同时新鲜 → 驱动冻结+告警
  （使用错误），只保留一个源；
- **黑匣子必录**：`js_blackbox.py` 新版含注入指令列（c1~c7 + 指令龄）
  —— "臂动了不知谁发的指令"类事故，对比 c 列与 q 列即可归因；
- **供电疑点（待查）**：09-18 曾有一次疑似供电瞬断（全关节低力矩
  坍缩 0.35s），未复现；若再遇"突然全关节软一下"，优先查电机电源；
- **纪律（不变）**：AI 不执行运动命令；标定与 control 不共存；异常 →
