# PD 参数整定流程（右臂 · MIT 模式）

> 2026-09-14。目标: 在**不破坏 sim2real 一致性与两方案对比公平性**的前提下,
> 按数据驱动流程把 kp/kd(/积分钳位) 调到基础扎实的状态。
> 适用: RL 与 MPC 两方案共用的底层增益(改一处, 两方案同步重基线)。

## 0. 铁律

1. **一次只动一个关节、一个参数**; 每次改动记录到 §9 的表格;
2. **先测后改**: 每个阶段先拿到当前值, 再动;
3. **微小步进**: kp 每步 ≤30%, kd 每步 ≤50%; 出现啸叫/持续振荡立即回退上一组;
4. **温度**: 整定在电机达到工作温度后做(连续运动 10min), 冷机数据不可比;
5. **同步义务**: 定稿后必须同步 `gen_real_config.py` 参数与 `zigzag_env.py`
   常量并重训 RL——单侧改 = sim2real 失配, `verify_deploy.py` 会拦;
6. **急停三级**随时待命; 微动用 `move_small.py`, 严禁标定工具与 control 共存。

## 0.5 论文经验公式基线(2026-09-14 定稿, 取代手工推测起点)

方法来源: arXiv 2508.08241v4 §S3(Unitree G1 全身运动跟踪 RL)。
**公式**: kp = I·ω², kd = 2Iζω, I = k_g²·I_rotor(折算转子惯量=armature);
**ζ=2 过阻尼**(只算转子惯量必然低估真实惯量), **ω=10Hz**(低频适度刚度,
柔顺优先); **残差幅值 α = 0.25·τ_max/kp**(动作最多动用 25% 额定力矩);
**力矩预算**(2026-09-17 更新为 v3: 操作员裁定短时 1.3×额定可接受,
J3/J4 按硬件 28 封顶; 训练 effort_limit 与 pd_screen 力矩门限已同步;
硬件 tmax 寄存器保持峰值 54/28/10 不动作物理余量)。

数据来源: DM-J4310-2EC V1.1 数据表 + Seeed 选型表(额定/峰值/减速比/
转子惯量) + 达妙官方产品页(8009P) + 官方 OpenArm IsaacLab 配置
(effort 40/27/7 = 峰值口径, 交叉印证)。

| J | 电机 | k_g | I_rotor | I_j(armature) | **kp** | **kd** | **τ_额定** | **α** |
|---|---|---|---|---|---|---|---|---|
| J1/J2 | DM-J8009P | 9 | 1.5e-4* | 0.0122 | **48.0** | **3.05** | **20** | **0.104** |
| J3/J4 | DM-J4340 | 40 | 2.0e-5 | 0.0320 | **126.3** | **8.04** | **9** | **0.0178** |
| J5-J7 | DM-J4310 | 10 | 1.8e-5 | 0.0018 | **7.1** | **0.45** | **3** | **0.106** |

*8009P 转子惯量数据表未公布, 1.5e-4 为保守估算 —— 拿到官方值后按
kp = I·3947.8, kd = I·251.3 重算(线性敏感)。

与旧增益的关键差异及影响:
- J1 kp 120→48, 腕部 30→7.1: **柔顺化**, 下垂回落到积分器承担
  → 阶段 1 复测腕部/肩部下垂是重点观察项;
- J4 kp 90→126 且 kd 2.2→8.04: 阻尼比 ζ(含连杆) 0.31→0.86,
  直接针对转移段粘滑抖动的主源;
- 力矩预算 54/28/10→20/9/3: J2 动态修正余量变小, α 联动收缩保证
  残差力矩 ≤25% 额定 —— 快速大修正会变"温和", 换取不顶爆额定;
- α 逐关节化: J3/J4 只有 0.018 rad(J4 kp 高, 同样力矩预算下行程小)。

**应用记录**: 2026-09-14 已同步 zigzag_env(KP/KD/TAU_MAX/ARMATURE/
action_scale) + rl_policy(ACTION_SCALE) + verify_deploy(审计常量),
RL 已按新基线重训; 真机侧应用命令见 §6(重新生成配置后重启 control)。

### 0.6 负载修正版 v2(2026-09-15, 用户查证后定稿)

**用户查证**: 公式里的 I 是否应包含负载? 论文原文核实的答案分三层:
1. 论文**刻意只用折算转子惯量**(理由: 连杆子树惯量随位形变化, 无单一
   正确值, "exact precision is not required");
2. 低估的补偿 = ζ=2 过阻尼;
3. 隐含前提(§S1): 转子折算惯量占轴总惯量"large—often dominant"——
   **G1 高减速比执行器才成立**。

**我们的臂不满足前提**: 准直驱 kg=9/10 的关节(J1/J2/J5-7)转子占比仅
1~4%; kg=40 的 J3/J4 占 23~32%。2026-09-14 真机实验与该判据完美对应:
kg=40 的 J3/J4 用论文值改善, kg=9/10 的关节全面恶化(腕部 3.6~7×)。

**v2 修正公式**: **I = k_g²·I_rotor + I_load,标称位形**(负载按标称位形
轴向惯量并入一次; ζ 回到 0.5~0.7, 不再需要 2 的补偿)。
验证性收敛: 腕部与 J1 用含负载公式 + ζ 0.5~0.7 **正好复现已验证的
旧增益**(30/1.5 与 120/3.6)——旧增益本就是"含负载经验公式"的实例。

| J | I_total | kp | kd | ζ | 力矩预算 | α |
|---|---|---|---|---|---|---|
| J1 | 0.45 | 120 | **7.4** | 0.5 | 20(额定) | 0.042 |
| J2 | 1.5 | **100**(70→100 治下垂) | **12.2** | 0.5 | 20(额定) | 0.050 |
| J3 | 0.8 | 70 | **7.5** | 0.5 | 27(峰值, J4 实测瞬态>额定) | 0.096 |
| J4 | 0.14 | **126.3**(论文值, 已验证改善) | **8.04**(ζ≈0.95 有效) | ~0.95 | 27 | 0.053 |
| J5-7 | 0.04 | 30(回已验证值) | 1.5(回已验证值) | 0.7 | 7(峰值) | 0.058 |

kd 说明: 表中为 ζ 目标解析值; 若真机引入可感噪声, 按流程"每步 ≤50%"
回退至 [6.0, 6.0, 4.0, 8.04, 1.5...]。α = 0.25·τ_budget/kp(逐关节)。
硬件 tmax 寄存器(54/28/10)保持不动 = 物理余量; 预算由策略/训练执行。
状态: **已同步三侧并重训**(train_v5), 真机应用命令见 §6/§8。

## 0.7 训练前离线安全筛选(2026-09-16 新增, pd_screen.py)

**动机**: PD 的任务级好坏不应等"训练完上机"才知道; 且评判必须以
尾部指标(max|e|/力矩峰值/ζ)一票否决, 均值只做次级 —— 大误差×kp
= 大回拉力矩, 安全第一。

**工具**: `仿真/mujoco_sim/pd_screen.py`(mujoco conda 环境):
- **全轨迹纯 PD 回放**: 复刻 rl_validate 同一套 MIT 律(250Hz)与积分器,
  指令 50Hz=q_ref 采样(等价真机 α=0 纯参考回放), 零训练零真机风险;
- **蒙特卡洛不确定性**(候选间同场景种子): 关节粘性/库仑摩擦(区间=
  zigzag_env 的 fric_visc/coul_range)、腕部负载 ±20%、指令延迟
  0/20ms、固件增益容差 ±5%;
- **硬约束一票否决**(任一场景违反即 FAIL): 仿真max|e|×sim2real系数
  ≤ 4°(真机口径)、max|τ_指令| ≤ 额定(v2 预算)、抬臂位形 ring-down
  ζ(J1-J4) ≥ 0.45(2° 阶跃, 同 §5 真机微动口径);
- **次级指标**只在安全集内排序: mean|e| / HF σ / ∫τ²(发热) / J2 下垂;
- **场景法保证**: N 场景全过 → 违反概率 ε≲3/N(Calafiore & Campi 2006)。

```bash
cd 仿真/mujoco_sim && conda activate mujoco
python pd_screen.py                 # v2 基线 × kp{0.8,1,1.25} × kd{0.75,1,1.3} × 12 场景(约11s)
python pd_screen.py --grav-ff 1.0   # 重力前馈对比(消下垂) → pd_screen_report_ff.json
python pd_screen.py --kp-csv ... --kd-csv ...   # 单组显式候选
```

**首次筛选结论(2026-09-16, 9 候选 × 12 场景, 产物 pd_screen_report*.json)**:
1. **全部候选未过 4° 真机门限**(×2 保守系数): 最好组 kp×1.25/kd×0.75
   折算 ~7.1° —— 与真机实测 max 7.29°(v2)吻合, 工具判据可信;
2. **误差尾部不在抬臂段而在走线换向**: 12 个场景 max 全部集中在
   t≈59.1s 的 J2 与 t≈68.8s 的 J4(方向急反转处), 20ms 指令延迟场景
   一致更差 ~0.5°;
3. **加刚度不是解药**: J2/J4 kp×1.5→×2.0, max 仅 3.61→3.28°
   (换向滞后由摩擦换向+缺前馈主导, 非刚度主导) —— 方向应是
   重力/速度/摩擦前馈(ILC 层)或让 RL 策略的残差去补偿;
4. **重力前馈主攻抬臂段**: 抬臂 max 1.60°→1.04°(−35%), 整体 max
   仅 −15% —— 各管一段, 两者叠加才是完整解;
5. **高 kd 有力矩风险**: kd×1.3 组 τ 峰值 3.38× 额定(速度项瞬态),
   kd 上调必须查 τ 指标, 不能只看误差;
6. **ring 到位率暴露抬臂权限**: 抬臂中点位形 2° 阶跃 2.5s 内 J2 仅
   到位 35%(重力梯度+积分时间尺度) —— 即真机"抬臂慢半拍"的孪生量化。

**已知局限(诚实口径)**: 孪生无关节柔性/线缆阻力/装配公差, ζ-ring
只作下界护栏(真机 §5 ring-down 仍是权威); 绝对误差偏乐观(校准系数
2.0), 排序与定位结论可靠。

### 0.10 训练侧事故复盘(2026-09-17, 三次训练的教训)

1. **effort_limit 必须用额定(TAU_MAX), 不是硬件峰值**:
   峰值钳位(54/28/10)对照实验中, 高频力矩内容直达物理 → 腕部 qd 频繁
   超 vel_lim, 行为惩罚(action_smooth/vel_lim/action_rate)从开局淹没
   探索信号(reward −220 起步, action std 涨到 1.25 发散)。额定钳位实为
   振幅限制器(低通), 逐项诊断(dbg)实证: vel_lim −0.46→−0.05。
   **验证方法**: train.py 已带分段 dbg 输出(track/vel/action_smooth/
   vel_lim/tail/fail 逐项), 训练健康度一看便知。
2. **评估口径权威序 = rl_policy(部署代码) > rl_validate(简化复刻)**:
   rl_validate 无 5Hz 残差低通/渐入/动作延迟建模, 首训 actor 在其中
   max 44° 而同源策略在 verify_deploy 口径下 6.08° —— 差异主要是
   评估口径非策略本身。下结论前先跑 verify_deploy。
3. **地面 USD 云端依赖**: 默认 Grid 走 NVIDIA 云, 网络抖动使训练无法
   启动; 本臂固定于台座无坠落自由度, 已直接不生成地面。
4. **checkpoint 选择**: 后期迭代缓慢退化复现(本轮 797@600→499@1200,
   逐项诊断: track 1.85→1.39 下滑 + action_rate/smooth 翻倍, action std
   稳定 0.2 排除熵漂移 —— 属 PPO 优势估计层面的优化退化, 二期课题);
   **决策: 以 verify_deploy 全绿的 600 迭代 checkpoint 定稿**
   (v1_2026-09-17_11-47-10, mean 2.88°/max 6.08°/τ 10.9Nm, 已部署
   actor_right.npz, md5 a955a59d), 不追 2000 迭代终点。

### 0.8 官方 MIT 五元组综合方案(2026-09-16 下午, 取代纯 PD 前馈讨论)

**官方代码启示**: `openarm_simple_hardware.cpp` 导出 position/velocity/
effort 三命令接口, MIT 帧 `{kp,kd,p_des,v_des,t_ff}` 全量下发 —— 官方
"重力补偿相关部分"就是这条 t_ff 通道本身(无现成重力计算); 官方
IsaacLab 只有 disable_gravity/高 PD, 无真补偿。我们的 zero_offset_hw
此前 v_des=0, 五元组只用 3/5。

**综合方案**(已全链路实现, 三侧同步):
1. **t_ff = G(q_ref)**, make_grav_ff **v2 改用真机描述 URDF 权威
   动力学**(重大发现: MJCF 质量是 make_mjcf.py 胶囊近似, 欠补偿 J2
   峰值 42%; 训练 USD 的 URDF ≡ 真机 URDF 逐项一致已审计);
2. **v_des = q̇_ref**(官方速度通道): kd 项从"阻尼绝对运动"变"跟踪
   参考速度", 直击 pd_screen 定位的换向滞后(J2@59s/J4@69s);
3. pd_screen A/B(12 场景): vref max 4.94→3.46°(−30%), 叠加 URDF
   前馈 mean 0.58→0.28°(−52%), τ/额定不变 0.39 —— 无力矩代价;
4. 消息 21 项=位置+速度+前馈(驱动 7/14/21 全兼容), 前馈钳位/速率
   钳位/断流归零/淡入淡出全套安全机制保留(见 rl_track README);
5. **控制律变更 = sim2real 口径变更, 必须重训**(v2 公式中心值 + 本
   可行域随机化), `verify_deploy.py` 全绿再分段上机。

**sim2real 校准**(2026-09-18 重标定, 反粘滑包 actor + 权威孪生):
60s 真机 mean 1.16°/max 3.46° vs 孪生 1.20°/3.07° → 系数 **1.0×(mean)/
1.13×(max)**, 旧系数 2.0/1.68(基于未对齐孪生)退役。pd_screen 默认
--sim2real-factor 建议改 1.2。2026-09-15 旧对(7.29/4.35=1.68)作废——
当时孪生质量/限位未对齐。

**两个实现教训**(2026-09-16, 对所有 MuJoCo 复刻有效):
1. **MIT 律必须 ≥250Hz**: 100Hz 离散 PD 腕部数值失稳(kd·dt/I_rotor>2,
   实验: 100Hz 发散到 19°+/10rad/s, 250Hz max 2.26°)。真机固件环 kHz
   级, rl_validate 的 250Hz 是已对真机验证的口径, pd_screen 沿用;
2. motor 执行器只有 forcerange(54/28/10), `actuator_ctrlrange` 是
   [0,0] —— 力矩钳位必须读 `actuator_forcerange`, 否则臂零力矩坠落。

**与训练/真机的衔接**(分层): v2 公式定中心值 → pd_screen 筛出
**安全可行域** → 该可行域直接作为训练 dr_kp/dr_kd 随机化区间

## 10. 风险与回退

- kd 过高: 放大速度反馈噪声 → 可闻啸叫/发热 → 回退一步;
- kp 过高: 撞击/顶限位时力矩冲击大(钳位兜底), 且 ζ 下降 → 配 kd 同步;
- 积分钳位↑: 下垂改善但换向时积分甩出 → 依赖 ±0.5rad 清零机制, 转移
  急停场景需重测;
- 全程门限: 任何阶段真机出现 watchdog TRIPPED, 停止整定, 回退上一组。
