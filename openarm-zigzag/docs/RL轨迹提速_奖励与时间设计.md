# RL 轨迹提速方案 —— 右臂之字形走线 (IsaacLab 训练 → MuJoCo 验证 → 真机)

> 2026-09-11。目标: 用强化学习策略替换 MPC 执行轨, 在保证**平稳、平滑、无晃动**
> 的前提下把右臂全程走线从 ~300s 压缩到 **~160s**。
> 本文档 = **设计历程**（奖励函数与时间分配的设计过程、实验数据、踩坑记录）。
> ⚠ **奖励数值与当前权重以后续定稿的** [`docs/RL训练结构详解.md`](RL训练结构详解.md) **§5 为准**
> （本文档记录的是设计过程，部分早期数值已被迭代取代）。代码入口见 §6。

## 1. 任务定义

完整任务链(一条参考轨迹, 全程连续不中断):

```
[home 静持 0.5s] → [转移: home→走线起点] → [之字形走线 18 行] → [转移: 终点→home] → [保持]
   软起(零速)        最慢 0.12 rad/s          水平 4.7cm/s / 竖直 14.2cm/s     最慢(0.12)      软停
```

走线几何 = 现役 `dense_zigzag_right.json`(1237 点, 5mm TCP 步距, x=0.30m 平面,
矩形 y∈[−0.416,−0.076] z∈[0.431,0.961], 行距 3cm, 夹爪垂直墙面)。

**速度层级**(用户要求, 关节速率口径):

| 相位 | 速度 | 全程用时 | 说明 |
|---|---|---|---|
| 转移(去/回零位) | TCP 与水平行一致 6.3 cm/s | 8.0s + 17.7s | 2026-09-14 用户决策: 转移不再单独用关节慢速(0.12 rad/s 爬行深陷摩擦带是转移抖动主因, 见 §8.4) |
| 走线水平行 | TCP 6.3 cm/s | ~110s | 中等 |
| 走线竖直换行 | TCP 名义 19 cm/s(3×水平) | ~12s | 最快; 实际受关节速率约束压到 ~9-12cm/s, 仍为最快 |

**总时长 143.6s**(目标 160s 内; `--target-total` 可调, 平稳性门限优先)。

参考轨迹实测核算(生成器自动打印):
- 峰值关节速度 0.36 rad/s(< 0.45 门限; 现役 MPC 约束 0.3, watchdog 4.0)
- 峰值关节加速度 4.9 rad/s²(瞬时, 预览可前馈; 现役 MPC a_max=1.2)
- 参考速度最大单步变化 0.10 rad/s per 20ms —— **无速度阶跃**
- 几何保真: 走线相位 TCP 对名义折线最大偏差 **2.71mm**(拐角圆滑化代价)

## 2. 为什么"时间/速度安排"放在参考轨迹里, 而不是奖励函数里

这是本方案的核心设计决策:

1. **总时长和速度层级是硬指标**, 奖励塑形(reward shaping)只能"鼓励", 不能
   "保证"。放在参考轨迹里 → 156.7s 由构造直接成立, 上机前即可审计。
2. **速度无突变**在参考层用数学工具保证(高斯卷积时间轴, 见 §3), 奖励层
   再叠加平滑项防策略自身抖动 —— 双保险, 且两层职责不耦合。
3. 奖励函数只负责策略最擅长的事: 在动力学约束(电机 kp/kd、重力、惯性)下
   **平滑、稳定、低抖动地跟上这条参考** —— 这正是 MPC 做不到提速的部分。

## 3. 参考轨迹生成 (`rl/zigzag_ref.py` → `ref_right.npz`)

四级流水线(每级都对应用户的一条要求):

1. **均匀重采样**: 全链(含转移段)按关节弧长 0.01 rad 重采样 —— 统一度量。
2. **Hann 滑窗圆滑**(半宽 4 点 ≈ 2cm TCP): 之字拐角与转移/走线交界的
   换向摊到小弧长上 —— 转弯不再产生速度方向阶跃; TCP 偏差仅 2.71mm。
3. **双约束时间分配**: 每步 T_k = max(TCP速率/相位速度, 关节步进/0.4rad/s,
   20ms)。转移段按 0.12 rad/s 摊时。→ 速度层级由此成立。
4. **高斯时间卷积**(σ=0.3s): 分段线性进度 u(t) 卷积后单调且无穷可导 ——
   相位间速度斜坡过渡、首尾零速软起软停, **数学上不存在速度跳变**。

**平稳性闭环**: 生成后核算峰值关节速度/加速度, 超 0.45 rad/s / 5.0 rad/s²
自动整体降速 8% 重生成(最多 10 次)。降速迭代与 160s 目标冲突时,
调 `--target-total`(如 165) 而不是放宽门限。

## 4. RL 问题建模

| 项 | 设计 | 与真机对应 |
|---|---|---|
| 控制频率 | 50Hz(物理 200Hz, decim 4) | 驱动 MIT 100Hz 内环, 策略 50Hz 发位置指令 |
| 动作 a∈R⁷ | 位置残差: `q_cmd = q_ref(t) + 0.25·tanh(a)`, 再钳位到软限位−3° | 走 `/right_mpc_position_commands` 注入通道(±6.5 绝对钳位 + 0.2rad/条速率钳位在驱动侧仍在) |
| 执行器模型 | **DM-MIT 复刻**: τ = kp·e_p + kd·e_v + I; I += ki·EMA(e_p)·dt, EMA α=1−exp(−dt/28ms), \|e_p\|>0.5rad 清零, I 钳位 ±[10,10,6,8,3,3,3] | 与 `zero_offset_hw.cpp` write() 逐项一致 |
| kp/kd | [120,70,70,90,30,30,30]/[3.6,3.0,2.0,2.2,1.5,1.5,1.2] | real_safety.yaml 同源 |
| 力矩上限 | [54,54,28,28,10,10,10] Nm | ESC 寄存器实测(标定 single_joint_test LIMITS) |
| 重力 | 开(积分器补偿下垂, 同真机) | 同 |
| 观测 (67维) | q(7,限位归一) + qd(7,/10) + 上一动作(7) + q_ref(t)(7) + 预览 q_ref(t+0.04/0.08/0.16/0.32)(28) + qd_ref(t)(7) + t/T(1) + 相位 one-hot(3) | 全部真机可得(/joint_states + 参考时钟), 无Privileged |
| Episode | 随机起点 t0~U[0, T−12s] + q 噪声 0.75°, 窗口 12s=600 步 | 部署时全mission连续滚动(策略平稳时不变) |
| 失败终止 | \|q−q_ref\|∞ > 0.30 rad(17°) | 真机对应 watchdog 软限位/急停兜底 |
| 域随机化 | kp/kd ±20%, ki ±30%, 力矩限 ±10%, 观测噪声 q 0.002rad / qd 0.02rad/s, 动作延迟 0~1 步 | 覆盖电机参数漂移与通信延迟 |
| 夹爪 | **fixed 并入 link7**(零自由度, 专用 USD `rl/openarm_right_rl.usd`) | 真机 ESC8 使能后原地锁定, 不参与跟踪 |

**两个必须的仿真稳定性修正**(实测定标得出, 缺一不可):

1. **折算转子惯量 armature = 0.02 kg·m²**: 纯 URDF 运动学惯量下, 腕部
   J5–J7 在 200Hz 显式力矩 PD 下零动作即发散到 20 rad/s。实测: 0.005 边缘
   (8.5rad/s), 0.01 起稳定, 取 0.02 留域随机化裕度。真机靠电机电流环 +
   减速器折算惯量天然稳定, 仿真必须补上这一项。
2. **夹爪必须 fixed**: 夹爪 prismatic 关节质量仅 0.017kg, kp=200 的 PD 在
   200Hz 下数值发散并污染整条 articulation 求解(表现为奖励 -70000、
   回合 2s 即失败)。改 fixed 并入 link7 后 7 关节全部稳定。

**奖励尺度提示**: 随机策略初期不应出现 -1e4 量级(价值拟合困难)。
`w_vel_lim` 的 relu 二次项在发散时主导奖励 —— 它是"发散指示器":
训练早期若该项仍巨大, 应先修物理稳定性, 而不是调奖励权重。

**GPU 管线注意**(已踩坑): `InteractiveSceneCfg.replicate_physics=False`
在本版本会触发 PhysX fabric device assert; 逐环境 DOF 属性写入
(armature/摩擦) 在 GPU 管线下不支持 → 模型随机化只保留执行器侧
(kp/kd/ki/力矩限, 纯 Python 缓冲); 崩溃后 Isaac Sim 进程不退出会占满
显存(16GB 卡上堆 6 个即 OOM), 重跑前需 `kill -9` 清理。

PPO (rsl_rl): 2048 envs, MLP 256×256×ELU, obs 不做经验归一(尺度已手工定)。

## 5. 奖励函数(逐项 + 权重 + 整定指南)

每步 r(t) 如下(50Hz, 各项含义/量纲/整定方向):

**正项 —— "跟得上"**

| 项 | 公式 | 初始权重 | 作用 |
|---|---|---|---|
| 位置跟踪 | w_p·exp(−‖q−q_ref‖²/2σ_p²), σ_p=0.03rad | 2.0 | 主任务。有界核: 大误差不爆炸梯度, 小误差高分辨 |
| 速度剖面跟随 | w_v·exp(−‖qd−qd_ref‖²/2σ_v²), σ_v=0.25rad/s | 0.6 | 锁时间层级: 慢段不抢跑、快段不拖沓 → 时长守住 156.7s |
| 完成质量 | 窗口末 +w_b·exp(−‖e‖²/2σ_p²) | 2.0 | 收尾稳定(对接"终点回零位"质量) |

**负项 —— "不晃、不抖、不撞"**(全部二次型 w·(x/std)²)

| 项 | 公式 | 初始权重 | 作用 |
|---|---|---|---|
| 动作变化率 | w_ar·‖a_t−a_{t−1}‖² | 0.03 | 指令平滑第一旋钮(抗抖动主手柄) |
| 关节加速度 | w_acc·‖qdd/10‖² | 0.004 | 抑制晃动/振荡(对应 mpc w_a 的角色) |
| 加加速度 | w_jk·‖jerk/50‖², jerk=Δqdd/Δt | 0.002 | 高频纹波(电磁噪声/发热相关) |
| 力矩载荷 | w_τ·Σ(τ/τ_max)² | 0.0015 | 远离饱和, 留稳定裕度 |
| 超速 | w_vl·Σ⟨|qd|−2.0⟩₊² | 0.5 | watchdog 安全限(4.0)的一半即罚 |
| 限位贴近 | w_lm·Σ⟨0.1−margin⟩₊² | 0.5 | 软限位内再留 0.1rad 缓冲 |
| 失败终止 | −1.0(且无完成质量项) | — | 17° 偏差即失败 |

**整定指南**(调参顺序, 一次只动一个):
1. 训练初期若跟踪误差降不下去 → w_p↑(2→4) 或 σ_p↑;
2. 收敛后实测晃动大(黑匣子 HF σ 对比基线 0.043/0.053) → w_ar×2 → 仍大则
   w_acc×2 —— 与 MPC 时代"w_a 是平滑第一旋钮"同一逻辑;
3. 实际用时明显 > 157s(拖沓) → w_v↑(0.6→1.0) 或 σ_v↓;
4. 换行段误差尖峰 → 先查参考(竖直段关节约束), 再 w_acc↓(0.004→0.002)。

**为什么没有显式的"时间奖励"(progress bonus)**: 时间层级已由参考+速度
跟随项锁定; 加 progress 会诱导"抢跑—等待"式极限机动(为省时牺牲平滑),
与稳定性目标冲突。若实测策略系统性拖慢, 优先动 w_v/σ_v。

## 6. 全链路使用

```
仿真/isaaclab_sim/rl/
├── zigzag_ref.py          # ① 参考轨迹(本文件 §3) → ref_right.npz
├── openarm_zigzag/        # ② IsaacLab 环境(MIT 执行器+奖励)
├── train.py               # ③ 训练:  ./isaaclab.sh -p train.py (headless)
├── play.py                # ④ 评估:  加载 checkpoint 滚参考, 出指标/图
└── export_actor.py        # ⑤ 导出 actor_right.npz (纯 numpy MLP 权重)
仿真/mujoco_sim/rl_validate.py   # ⑥ MuJoCo 验证(同一 npz, MIT 100Hz 复刻)
real/right/rl_track/rl_exec.py   # ⑦ 真机执行节点(50Hz, 只发布不驱动)
```

sim2real 一致性: ②与⑥与⑦使用**同一份执行器数学**(§4 表), 同一份参考
npz, 同一份 actor npz(numpy 前向, 无框架依赖)。

## 7. 风险与回退

- **训练不达标**: 参考轨迹本身可直接喂现役 `mpc_exec.py`(协议不变) ——
  参考/奖励的成果与 RL 解耦, 即使 RL 失败, "156.7s 平滑参考 + MPC"仍可部署
  (预计 ~160s 达成, 平滑性优于现 0.4 倍速轨)。
- **真机抖动**: 三级处置: rl_exec 输出再加一阶低通(默认关) → w_ar/w_acc 加倍
  重训 → speed 回退(--target-total 175)。
- **安全**: rl_exec 沿用驱动注入通道的全部既有防护(速率/绝对钳位、watchdog、
  estop 停流回落 JTC); AI 不执行任何真机运动命令。

### 8.1 标定变更事件与处置(2026-09-11 下午)

后果: 旧之字形稠密轨迹的 J6 峰值 0.8083 rad **超出新硬限位 8°**,
1164/54838 个样本落在指令盒(软限位−3°)外 → 策略按现状无法安全部署。
**现役 MPC 主线同样越界 8°**, 属项目级问题而非 RL 独有。

处置(已执行): 备份旧产物到 `archive/旧标定产物_20260911/` → 用新标定重做
工作区扫描与之字形(新矩形 y∈[−0.386,−0.056] z∈[0.408,0.978], 20 行) →
重生成参考 → 重训 → 重新验证。

**根因与修复**: `zigzag_ref.py` 与 `zigzag_env.py` 里各有一份**硬编码的
home/软限位副本**, 重标定后不会自动更新 —— 这正是"仿真产物与真机配置
悄悄失配"的典型机制。现三处(含 `rl_policy.py`)全部改为从
`real/right/config/real_safety.yaml` 读取, 并新增离线验证脚本
`real/right/rl_track/verify_deploy.py` 把这类失配在**上机前**拦下
(它已经拦下过一次)。

**新参考核算**: 总时长 150.5s(转移出 11.1 + 走线 118.7 + 转移回 19.6);
水平 6.21 cm/s / 竖直 18.62 cm/s(3×) / 转移 0.12 rad/s(最慢);
峰值关节速度 0.424 rad/s(watchdog 4.0 的 9× 裕度), 速度零阶跃,
几何保真 2.74mm。

**结论**: 时间目标达成(原 156.6s; 新标定下 150.5s), 平滑性显著优于 JTC 主线(3~4×),
稳定性由 MIT 执行器内生保证(积分前馈补偿重力下垂, 全程无失败终止)。
TCP 精度(12.9mm)低于 MPC 轨(1.3mm) —— 若后续任务对 TCP 精度要求更高,
整定方向: 收紧 σ_track(0.10→0.06) 与 w_track(2.0→3.0) 重训。

### 8.4 转移段抖动专项(2026-09-14 下午, 数据驱动)

用户反馈 home↔起终点转移段抖动明显。黑匣子分相位分析定位:

| 相位 | HF σ (J1/J2/J4) | 特征 |
|---|---|---|
| **转移出** | **0.091 / 0.117 / 0.094** | 重灾区; 残余速度频谱主峰 **~11Hz**; 起步 0.9s 内 J4 瞬态 1.02 rad/s |
| 走线 | 0.036 / 0.050 / 0.040 | 正常 |
| 转移回 | 0.023 / 0.050 / 0.032 | 与走线相当 |

诊断(2026-09-14 二次修正 —— 含力矩通道分析后的最终归因):
主导成分是**爬行速度下的低频速度波动(粘滑)**, 而非先前所述 11Hz 高频
hunting(8-15Hz 带内能量仅 0.02 rad/s RMS, FFT 峰值归因有误)。证据链:
① 速度依赖性 —— 参考 0.11 rad/s 时残余速度 RMS 占参考速度 61~93%
  (转移出 J4: mean 0.051 vs 参考 0.10, std 0.067, 6.8% 时间倒退);
  参考 0.25(走线)时占比降到 25~33%;
② 频段吻合关节固有频率 —— J4 波动峰 4-8Hz ≈ √(kp/I)/2π ≈ 4.3Hz
  (kp=90, I≈0.14, ζ≈0.31 欠阻尼), 粘滑转折反复激发欠阻尼模态;
③ 方向不对称 —— 转移出(抬臂, 重力对抗摩擦)比转移回(放臂)抖 2 倍。
策略 50Hz 输出是次要激励源(残差变化率 ≤0.5°/s 本身平滑)。

**已实施(部署侧, 不需重训)**:
1. 策略残差一阶低通, 截止 5Hz(`rl_policy.py` `lp_freq`, `--lp-freq` 可调):
   参考带宽 ≤3Hz 通过 86%, 11Hz 颤抖增益 0.43, 直流(重力补偿)完全保留;
2. 启动残差渐入 1.5s(`--fade-s`): 消除起动静息→运动的切换冲击
   (t=0.9s 的 J4 1.02 rad/s 瞬态即此)。
MuJoCo 回放复核: 跟踪误差 mean 1.51° 不变, 回放 HF σ 0.0098/0.0232。

**已实施(零成本实验路径)**: `rl_exec.py --transfer-boost 1.5` ——
部署时转移段时间轴加速 1.5×(实际转移关节速度 0.12→0.18, 冲出摩擦带;
相位界余弦过渡无速度阶跃; 观测里 qd_ref 同步缩放保持与真实运动一致)。
总时长 150.5→139.6s, 走线段不受影响。MuJoCo 回放 A/B: 转移段跟踪误差
不升反略降(出 5.57°→5.09°, 回 7.04°→6.80°)。**真机 A/B 协议**: 先后跑
`rl_exec.py --max-t 15 --log-csv` 与 `--transfer-boost 1.5 --max-t 15
--log-csv`, 用 analyze_real_run.py 对比转移段残余速度 RMS 与目测。
**已固化(2026-09-14 用户决策)**: 转移段速度与水平行统一(TCP 6.3cm/s,
等效原 0.12 rad/s 的 ~1.4×), 直接写进 `zigzag_ref.py` 并重生成参考
(总时长 143.6s)+重训。`--transfer-boost` 参数保留(默认 1.0)用于
进一步实验; 参考内建加速后一般无需开启。

**其他可选**: 驱动侧单独放大 J2 `integ_clamp`(10→15) 改善 J2 下垂与
积分器 hunting; 关节 kd 提阻尼(ζ 0.31→0.6) —— 两者都影响 MPC 方案共享
的增益整定, 对比实验前不建议动。
