## 3. 硬件层

### 3.1 电机布局（实物 ESC 序号 → 关节）

| ESC | 电机型号 | 物理关节 | 说明 |
|-----|---------|---------|------|
| ESC1 | DM8009 | 肩俯仰（前后摆/抬臂） | 重力最大，tmax 实测 54 Nm |
| ESC2 | DM8009 | 肩偏航（绕竖直轴） | |
| ESC3 | DM4340 | 肩滚转（大臂自转） | 竖直零位附近接近奇异 |
| ESC4 | DM4340 | 肘俯仰 | tmax 实测 28 Nm；曾锁存故障（断电循环恢复） |
| ESC5 | DM4310 | 腕滚转 | tmax 实测 10 Nm |
| ESC6 | DM4310 | 腕俯仰 | |
| ESC7 | DM4310 | 腕偏航 | **方向镜像：channel_sign=-1** |
| ESC8 | DM4310 | 夹爪 | 真机管线不控；使能后原地 MIT 锁定（设计行为） |

- 历史教训：ESC1/ESC2 与模型对调的判断（2026-09-04）**已被真机证伪并回滚**，
  当前 `channel_map` = 恒等 `[1,2,3,4,5,6,7]`，仅 J7 sign=-1。
- 电机全部为 MIT 模式（`标定/openarm_calibration/scripts/check_esc.py --fix`
  可复查/修复，全 MIT=1.0 为正常）。
- 实测寄存器限参见 `single_joint_test.py` 的 LIMITS 表：
  J1/J2=(12.5,45,54)、J3/J4=(12.5,20,28)、J5-J8=(12.5,50,10)（VMAX 与官方
  表不同，J3/J4 VMAX=20）。

### 3.2 CAN 链路

- 适配器：gs_usb USB-CAN-FD，SocketCAN 接口 `can0`。
- 参数（由 `标定/openarm_calibration/scripts/can_up.sh` 设置）：
  `bitrate 1000000, dbitrate 5000000, fd on, sample-point/dsample-point 0.75,
  dsjw 2, txqueuelen 100`。
- 两个已知硬件坑：
  1. gs_usb **不支持 Bus Off 自动重启**（restart-ms 无效）——用手动 `ip link`
     或 `can_up.sh`；
  2. gs_usb **USB 自动挂起**导致接口参数全对但 RX/TX 恒 0——每次重启电脑/
     插拔适配器后必须跑 `can_up.sh`（内含禁用全部 USB autosuspend）。
- 仿真总线：`vcan0`（`标定/openarm_calibration/run_simulation.sh` 创建），
  标定节点在仿真/实机之间**唯一区别是 `can_iface` 参数**。

### 3.3 应急手段

三级降级：程序停流（Ctrl+C，停流保持）→ `/safety/estop` 软急停 → 物理断电。
ESC 类锁存故障（如 ESC4 力矩不跟指令）处置：断电 10s → `can_up.sh` →
`check_esc.py` 验证 → 单关节微动判定。

## 4. 底层驱动层

### 4.1 C++ 主线驱动：`ZeroOffsetHW`（真机唯一在用）

**位置**：`real/common/ws/src/openarm_zero_hw/`
（`src/zero_offset_hw.cpp`、`include/openarm_zero_hw/zero_offset_hw.hpp`，
已编译到 `real/common/ws/install`；驱动完全臂无关，左右臂共用）。

**性质**：ros2_control `SystemInterface` 插件（pluginlib 导出
`openarm_zero_hw::ZeroOffsetHW`），基于官方
`openarm_hardware/openarm_simple_hardware` 修改；底层 CAN 收发用官方
`openarm::can::socket::OpenArm`（openarm_can 库，来自
`~/桌面/openarm/openarm_ros2_ws`）。

**电机表**：send 0x01–0x07 / recv 0x11–0x17（官方默认）；`hand=hold` 时追加
ESC8（send 0x08 / recv 0x18，DM4310）。型号固定
DM8009×2 / DM4340×2 / DM4310×3（+夹爪 DM4310）。

**与官方实现的关键差异（全部出于真机安全/精度）**：

| 项目 | 官方行为 | 本驱动行为 |
|---|---|---|
| 零位换算 | 电机角度直接当 URDF 关节值 | `urdf = s*motor − d`，`MIT 目标 = s*(urdf + d)`，d1..d7 必填（缺则拒启） |
| on_activate | 使能后 2s 大增益插值冲向电机零位（危险） | **使能后锁定当前位形**（读当前位形作为命令 → write 刚性保持） |
| 增益 | 硬编码 | 参数化，三级回退：kp1..kp7 逐关节 → kp 逗号列表 → 内置默认 |
| 夹爪 | — | `hand=false` 不接触 ESC8；`hand=hold` 使能后以 hand_q0 定点锁定（默认 kp10/kd0.9），不暴露 ROS 命令接口 |

**软件积分器（重力补偿，驱动内置）**：write() 中对电机系误差积分
（EMA α=0.3 平滑，|误差|>0.5rad 清零防饱和，钳位 ±clamp Nm），以 tau 前馈
叠加进 MIT 指令。把每关节 1~3.4° 稳态重力下垂压到 ≤1°。`ki=0` 即关闭。

**MPC 指令注入通道（write() 指令源双路）**：内部节点
`zero_offset_hw_mpc` 订阅 `/left_mpc_position_commands`
（Float64MultiArray，7 关节）。流新鲜（<0.2s）时 write() 优先采用，
断流自动回落 JTC；每条消息速率钳位 0.2rad、绝对钳位 ±6.5rad（防御异常
发布器）。指令源切换会打日志 `指令源切换: MPC 流 / JTC`。

**生命周期**：
- `on_configure`：只收帧刷新状态，不使能；
- `on_activate`：enable_all → 读当前位形 → 换算 URDF 系 → 锁定；
- `read()`：refresh_all + recv_all，位置/速度/力矩乘 channel_sign 并减 d；
- `write()`：100Hz（controller_manager update_rate），组装 MIT 参数帧
  `mit_control_all` + `recv_all(100)`；
- `on_deactivate`：清积分器 → disable_all ×3（防再使能跳变）。

**通道映射**：`channel_map`（URDF 关节 i ← ESC 序号，必须 1..7 不重复排列，
非法拒启）、`channel_sign`（±1）。当前恒等 + J7=-1。

### 4.2 Python 标定栈驱动：`dm_canfd.py`

**位置**：`标定/openarm_calibration/openarm_calibration/dm_canfd.py`。
只依赖标准库（socket/struct），帧编解码 1:1 对齐官方 openarm_can C++ 库。

**CAN ID 约定（关键常量）**：

| 帧 | ID | 载荷要点 |
|---|---|---|
| 使能/失能/置零 | ESC_ID (0x01–0x08) | 7×0xFF + 末字节 **0xFC/0xFD/0xFE**（0xFE=set_zero 写电机 flash） |
| 状态反馈 | ESC_ID + 0x10 | 8B：state_code, q(16bit), dq(12bit), tau(12bit), t_mos, t_rotor |
| refresh 触发反馈 | 0x7FF | [ESC_ID 小端 2B, **0xCC**, 0…] |
| 参数查询/写入 | 0x7FF | [ESC_ID 2B, **0x33**, RID…] / [**, 0x55**, RID, u32] |

**MIT 控制帧**（`build_mit`）：q∈±pmax 16bit、dq∈±vmax 12bit、
**kp∈[0,500] 12bit、kd∈[0,5] 12bit**、tau∈±tmax 12bit（`d2u/u2d` 与官方
double_to_uint 一致）。

**类结构**：`CanFdBus`（`CAN_RAW_FD_FRAMES=5`，`CANFD_BRS=0x01`，send 64B
补齐 + ENBUFS 重试 25×2ms，recv 兼容 FD/经典帧）、`parse_state`/
`parse_param`、13 型号 FALLBACK_LIMITS (pMax,vMax,tMax) 表、
`CTRL_MODE_MIT=1`、STATE_CODES 表。

参数查询 RID：`RID_MST_ID=7, RID_ESC_ID=8, RID_CTRL_MODE=10,
RID_PMAX/VMAX/TMAX=21/22/23`。

### 4.3 链路工具与历史栈

- `标定/openarm_calibration/scripts/can_up.sh`：can0 down → 设参 → up →
  禁 USB autosuspend。**每次上电/插拔后必跑**。
- 【存档】`motorbridge(libdm_device.so)` + `archive/arm_dm_control.py` +
  `archive/arm_trajectory_bridge.py`：历史路线（2026-09-11 移入 archive/）（达妙 DM-USB2FDCAN 设备、6 电机、
  pos_vel 模式、电机原始编码器空间无 URDF 零位对齐）。已被主线替代，
  勿再扩展；其"两个独立 SingleThreadedExecutor 规避 rclpy wait set 竞态"
  的设计笔记见该文件头注释。

## 5. 中间层

### 5.1 ros2_control（实时控制骨架）

- `controller_manager`：**update_rate 100Hz**（`real/<side>/config/ros2_controllers_real.yaml`）。
- `left_joint_trajectory_controller`（JTC）：command 仅 position，state 仅
  position/velocity（jazzy JTC 不接受 effort 状态接口）；
  `allow_partial_joints_goal: false`，`goal_time: 0`。
- 轨迹容差按刚度分档（防 PATH_TOLERANCE_VIOLATED 误中止）：
  J1 traj 0.20/goal 0.15；J2/J4 0.15/0.10；**J3 0.40/0.30（竖直奇异）**；
  J5-J7 0.35/0.25；stopped_velocity_tolerance 0.05。
- `joint_state_broadcaster`：发布 `/joint_states`（下游全靠它）。

### 5.2 MoveIt2（规划层）

- launch：`real/left/config/left_real_moveit.launch.py`（右臂对应 `real/right/config/right_real_moveit.launch.py`）（move_group + RViz +
  safety_watchdog 常驻）。OMPL 管线，KDL（`kinematics.yaml`）。
- 真机 URDF：`real/left/config/openarm_left_real.urdf`（右臂对应 `openarm_right_real.urdf`）（gen 生成，软限位写入
  limit，手指两关节改 fixed，ros2_control 块指向 ZeroOffsetHW 并内嵌 d1..d7）。
- 关键参数：
  - `trajectory_execution.allowed_start_tolerance: 0.0`（平铺顶层键——嵌套
    不生效，治 MOTION_PLAN_INVALIDATED_BY_ENV_CHANGE）；
  - `real/<side>/config/joint_limits_real.yaml`：规划速度 J1-J4 0.15 rad/s、
    J5-J7 0.2 rad/s，加速度 0.2/0.3（原官方 OMPL 峰值数百°/s，真机不可用）。
- **官方包补丁提醒**：`install/openarm_bimanual_moveit_config/.../joint_limits.yaml`
  已补加速度限位（.bak 备份）；**重建官方包后必须重打**。

### 5.3 安全中间层：`safety_watchdog.py`

**位置**：`real/<side>/config/safety_watchdog.py`（由对应臂的 *_real_moveit.launch.py
以独立进程常驻）。

- 触发条件（三选一）：
  A. 软限位越界（real_safety.yaml + 2° 余量，连续 5 帧）；
  B. 速度异常（>4 rad/s，连续 3 帧）；
  C. `/safety/estop` 人工急停（Bool true）。
- 响应：状态 `TRIPPED → RETURNING`；直接调 JTC action 的 `cancel_goal`
  服务（全零 GoalInfo=全部取消；rclpy 无 cancel_all_goals API）→ 不经
  MoveIt 直接发慢速回位轨迹到标定初始位形（0.25 rad/s 限速）。
- 复位：`/safety/reset`；状态发布 `/safety/status`。
- 另有 `/joint_states` 断流 >1.5s 报错监控。
- **已知贴线问题**：home 处 J4 距触发线仅 ~1.1°（详见 §11）。

### 5.4 坐标/配置换算链（贯穿全系统）

## 7. 端到端数据流

### 7.1 真机主线（JTC 路径）

```
dense_zigzag.json
   │  zigzag_moveit.py（MoveIt 规划/重定时，allowed_start_tolerance=0）
   ▼
/execute_trajectory（失败两次 → JTC 兜底直连）
   ▼
left_joint_trajectory_controller（JTC，容差分档监视）
   ▼  position command（URDF 系）
ZeroOffsetHW.write() @100Hz
   │  指令源选择（JTC 或 MPC 流）→ target_m = s*(cmd+d)
   │  + 积分器 tau_ff（ki*∫err, EMA, 钳位）
   ▼  MIT 帧（kp,kd,q,dq,tau）
openarm_can → SocketCAN can0（CAN-FD）→ gs_usb → 电机 ESC1-8
   ▲
   │  状态反馈帧（q/dq/tau，recv=ESC_ID+0x10）
ZeroOffsetHW.read()：pos = s*motor − d
   ▼
/joint_states → joint_state_broadcaster
   ├→ safety_watchdog（限位/速度监视 → 取消 JTC → 回 home）
   ├→ RViz / move_group（规划起点）
   └→ js_blackbox.py（100Hz CSV 归因）
```

### 7.2 MPC 实验轨（旁路 JTC 的指令注入）

```
dense_zigzag.json → mpc_exec.py（参考重采样 + PreviewMPC 滚动优化）
   → /left_mpc_position_commands @100Hz
   → ZeroOffsetHW.write()（<0.2s 新鲜则优先于 JTC；速率/绝对钳位）
   （断流自动回落 JTC；/safety/estop 或 status 异常 → mpc_exec 停流）
```

### 7.3 标定 → 部署的配置流

```
标定节点(calibration_node, root) ──0xFE set_zero──▶ 电机 flash
        │ 写 zero 文件（zero_position_rad / pos/neg_limits_rad）
        ▼
gen_real_config.py ──▶ real_safety.yaml（watchdog/工具/轨迹生成共用）

```

## 12. 安全纪律与运行约束

- **AI/协作者不执行任何让机器人运动的命令**；写代码/配置/给指令，用户
  执行并回传现象。
- **标定节点与 control/MoveIt 绝不能同时运行**（都直接驱动电机）。
- 每次上电流程：`can_up.sh` → 终端 A control → 验证日志（`MPC 指令通道
  已订阅`、`积分器 ki=[12,...]`、kp 行、d 行）→ 终端 B MoveIt+watchdog →
  check_states → to-home → 再执行任务。
- 异常 → 停步 → 贴日志 → 分析后再动；急停三级降级：停流 →
  `/safety/estop` → 物理断电。
- 重新标定（start）后必须：重跑 gen_real_config.py → 重启 control →
  重新核对 dense 限位合规。
- 启动日志"电机在线 7/8"多为首轮瞬时丢帧，用 /joint_states 两次 echo 复核
  （8 路都在变即正常；ESC8 不控是设计行为）。
- 残留进程 DDS 污染：重启前 `pkill` 全套（模式加方括号防自杀，如
  `[m]ove_group`）。
- colcon build 统一用 `/usr/bin/python3`
  （`--cmake-args -DPython3_EXECUTABLE=/usr/bin/python3`），防 conda 劫持。
